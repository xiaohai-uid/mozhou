# 墨舟 Landing「夜墨编辑工作室」设计方案

**状态：** 用户已确认，2026-08-16

## 目标

保留墨舟当前的深色、紫色动作色和编辑器感，把公开首页从“暗色卡片集合”升级为更完整的中文写作产品品牌入口。第一轮只改公开 Landing 的视觉结构与交互表现，不改变认证、API、业务数据或应用内路由。

## 现状判断

- 首屏的左文案右章节卡方向成立，产品定位清楚。
- 深色编辑室与紫色动作色可以继续使用，但当前紫色过于集中，细边框、卡片和标签造成视觉噪声。
- 功能区的 6 格网格在桌面端出现最后一张卡片单独落在左下角的空洞，网格节奏不完整。
- 每个区块都使用紫色等宽 eyebrow，页面节奏公式化。
- 当前页面使用系统字体栈，缺少更明确的品牌排版性格。
- 入场动画在首帧可能让主要内容暂时不可见，必须保留可用内容并兼容 reduced motion。
- 390px 当前没有检测到横向溢出，但功能区过长且卡片重复，需要压缩移动端节奏。

## 设计方向

名称：**夜墨编辑工作室**。

保留墨黑底、冷紫动作色、编辑器预览和中文大标题，调整为更克制的“纸白正文、墨色表面、单一紫色强调”体系。按钮和标签可以使用胶囊形，但主要容器使用统一的中等圆角，不让所有元素都变成胶囊。

## 页面结构

### 顶部导航

- 保留 64px 左右的轻量导航。
- Logo 使用更稳定的品牌标记，不再依赖紫色渐变制造唯一层次。
- 保留“登录”和“开始写作”，但只让“开始写作”成为明确的主按钮。
- 所有可交互元素拥有统一 hover、active、focus-visible 状态。

### Hero

- 保留左右分栏。
- 左侧保留“让 AI 与你共同创作”的核心标题和一个主 CTA。
- 右侧升级为更像写作台的章节编辑预览，补充章节状态、AI 续写状态和写作元数据。
- 容器对齐到页面最大宽度，避免右侧视觉被裁切。
- 入场动画只负责渐进增强，首帧不能依赖动画才显示内容。

### 功能区

- 保留 6 项能力，但重排为完整的 dense bento 结构。
- “写作对话”作为主要视觉单元跨两行，其余能力围绕它形成完整网格。
- 减少重复编号和紫色强调，将颜色留给真正的主能力与交互状态。
- 只保留一个功能标签组，避免每张卡都像同一模板复制。

### 产品预览

- 保留真实语义的 MiniChat 组件。
- 增加“生成、停止、插入正文”式状态信息，让它更像产品工作流而不是静态截图。
- 输入框继续保持演示性质，不引入后端逻辑。

### 长文记忆

- 保留人物、设定、章节三种内容。
- 通过错位、关系线或更明确的档案层级呈现记忆结构。
- 减少三张同质卡片的感觉，保持编辑档案气质。

### 理念与 CTA

- 理念区继续安静，但改成更清晰的三项承诺，不再依靠大量编号制造结构。
- CTA 区保留单一主动作与次动作，减少重复标签。
- 页脚补足统一的品牌文字节奏，不改变导航范围。

## 响应式与可访问性

- 验收视口：1440、1024、768、390。
- 768px 以下多列布局明确退化为单列，不保留桌面端偏移。
- 390px 不允许横向溢出，按钮和输入控件保留可触达尺寸。
- `prefers-reduced-motion: reduce` 下取消位移动画和闪烁光标。
- 保留 `:focus-visible` 焦点环，保证文本和按钮对比度。

## 不在本轮范围

- 不改 API、数据库、认证、业务状态和应用内工作台。
- 不新增图片依赖、动画库或字体包，先使用现有依赖和可用字体栈。
- 不做部署，不修改 Cloud Run 配置。

## 验收标准

1. 首页在四个目标视口下结构完整，没有横向溢出。
2. 功能区桌面端不再出现孤立卡片和大块未解释空白。
3. 首帧主要文案和 CTA 可见，动画失败或 reduced motion 时仍可用。
4. 所有交互元素有 hover、active、focus-visible 状态。
5. TypeScript、现有测试和 Next.js production build 全部通过。
