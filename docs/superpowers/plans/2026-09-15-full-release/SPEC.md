# 墨舟正式版范围与验收规格

## 已批准与工程建议

批准：完整现有应用、公网创作网站、Windows 应用、无同步、微信+支付宝、19/39 元月档、优先大厂免费额度。
本文件的实现路径/容量阈值是本次工程建议；不得解释成用户已经具备商户资质、云账号、无限免费模型或付费授权。

## 架构边界

- 唯一主线：apps/web + packages/*。app/ 为遗留参考，不重新部署其旧前端，不新建另一套小说内核。
- 两种明确运行模式：local 与 hosted。不能靠 Host/Origin 猜模式；启动时验证配置。
- local：Windows 安装器携带 Node 后端与现有 packages，监听回环动态端口，作品在用户选定目录。Tauri 必须真正管理后端启动/退出；静态 WebView 不是完成。
- hosted：同源 HTTPS UI + Node API，单节点、单写进程、持久卷。书根由服务端以已认证 userId + bookId 查询得到；客户端绝不发送服务器文件系统路径。
- 首发不承诺水平多实例和共享 SQLite。单实例使用部署锁确保第二写进程启动失败；跨进程的写保护必须可验证。
- 账号建议 Supabase Auth（使用维护中的 SDK 验证用户，不自写密码/短信系统）；业务订单/权益放服务器专用事务数据库，和每本书的正典/投影分开。可复用已用的 better-sqlite3，禁止浏览器直写订单。
- 网站与 Windows 共用账号/付费权益服务。Windows 本地书不因登录而上传；官方模型请求仅上传本次明确使用的上下文并给出说明。

## 托管决策（2026-09-15 官方资料核验）

保留当前 Node + 文件系统 + 原生 SQLite 路径；不要为了“免费”把整个数据平面改成 Workers/D1。
优先探测 Oracle Cloud Always Free 的可申请实例+持久块存储（不是假设已有）；Cloudflare 可用于 DNS/HTTPS 接入，Supabase 免费额度可用于身份。
部署前必须实际测目标 region、架构、Node native 模块、磁盘持久性、连接模型/支付服务、国内访问和费用控制。资源申请失败则阻塞公网发布，不能自动升级付费。

- Oracle 官方当前文档列 A1 每月 1500 OCPU 小时/9000 GB 小时免费额度，同时说明闲置资源可能回收；不能照搬旧的 4 核/24 GB 宣传。
- Vercel Hobby 限个人非商业用途，不作为收费站默认后端。
- Render Free 无持久磁盘，不能放唯一正文或 SQLite。
- Cloudflare Workers 的 fs 是虚拟/临时文件系统，不等于持久 Node 主机。
- Supabase Free 有数据库/流量额度、闲置暂停，不能承诺商业 SLA。业务库和卷要有独立可恢复备份。

以上免费资源只作为首发候选；T01 的 live probe 与实际条款决定是否可用。0 元服务器不是完整运营成本为 0，域名、商户、邮件、模型、签名可能另需条件。

## 发布不变量

I01 未经 Accept 的生成只改变候选区，不改正文、正典、revision 或 manifest 基线。
I02 所有写入都绑定用户/书/章/操作/源版本；CAS 失败返回 409，保留用户文本。
I03 一个 candidate 或 commit 请求重试只生效一次；不同 body 复用 idempotencyKey 必须 409。
I04 外部改盘、其他窗口保存、生成期间编辑/取消/退出、断流、恢复均不得静默覆盖。
I05 所有耗时 await 后，持久化前重查 ownership、任务开闭状态、源 revision/hash；不能只在入口检查。
I06 质量报告锚定 draftRevision/hash/receipt/ruleset/model；正文变化即 stale，不能拿旧报告定稿。
I07 公网拒绝路径字段/越权书/伪用户身份；列表、下载、任务、账本、备份、分镜一样受保护。
I08 付费成功来自校验过的服务端回调/主动查单；金额/商户/应用/币种/订单身份完全匹配、数据库唯一约束防重。
I09 模型 Key 不进前端静态包、日志、导出、备份或小说目录；模型与网页内容永远是数据，不是权限命令。
I10 发布资产包含已验收源码构建，解压/安装后可用；不得依赖本开发机绝对路径、node_modules 或旧 dist。

## 最终验收负载（建议首发合同，不是已测性能）

- 50 章真实生成与采纳/审查/定稿/重启回读；每章目标 2000–4000 中文字，短章需标注理由。不可用空包或合成两章冒充。
- 再用确定性生成的 500 章、总 150 万字数据集验证打开、检索、保存和备份；这项只证明规模，不证明文学质量。
- 公网 10 独立用户/20 浏览会话，2 个同时模型生成。超过生成容量进入有界队列或 429，不假成功。
- 同一本书双窗口编辑、2 次相同请求、20 路竞争付款回调/额度预留；全部满足 I01–I09。
- 目标主机：本地不含网络的普通正文保存 p95≤500ms；公网轻量元数据 API p95≤1s；保存确认后重启已保存正文丢失=0。
- 模型连接最长 20s，流空闲 30s，总任务 180s；结构化修复最多2次；每任务最多3次上游尝试且受成本预算约束。不要重试已经确认完成的收费任务。
- 2 小时创作混合负载；每 10 分钟保存与任务计数核验；内存/磁盘不持续失控增长。
- 维护备份按日生成，服务端最大备份数据损失窗口≤24h，恢复≤30分钟；当前运行中已确认写入的恢复与跨机器灾备分开报告。
- Windows 标准用户、无 Node/pnpm/Git 的干净机器首装；中文/空格目录；断网阅读编辑；升级中断、重装和卸载保留用户作品。
