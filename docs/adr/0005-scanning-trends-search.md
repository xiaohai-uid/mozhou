# ADR-0005：扫榜、趋势与搜索通道（2026-08-14）

## 状态
Accepted（grill Q1-Q8 用户确认）

## 背景
线上扫榜仅 2 个番茄榜且无历史存储，无法回答「流量趋势」；书源搜索此前返回 PUA 乱码+无关榜单（已降级修复，2026-08-14 缺陷轮）。调研确认：番茄榜单无签名需求（detail-ssr 可行）；搜索 API 需 msToken + a_bogus 签名，有开源实现可移植；crawl4ai 无头渲染被风控拦截。

## 决策

1. **榜单配置**：核心榜型（热门/新书/阅读/完结 × 女频/男频 × 短/长篇）全量接入，约 8-16 个榜；每榜前 20 名；题材榜二期。榜 ID 以实测页面菜单为准。
2. **快照存储**：新建 `ranking_snapshots` 表（board_id, book_id, rank, captured_at, 唯一约束 board+book+captured_at）；每次扫榜全量落库；保留 90 天自动清理。
3. **扫榜触发**：每日 1 次自动（Cloud Run 定时或惰性触发）+ 手动按钮；对齐番茄日更节奏。
4. **趋势呈现**：榜单行内涨跌标签（较上次快照）+ 新进/跌出标记 + 上升最快 TOP5 / 新进 TOP5 横区；单书曲线页二期。
5. **搜索**：本地书目检索（扫榜积累的 book index 内模糊匹配），页面标注「数据来自扫榜库」；废除联网伪造路径。
6. **生产爬取通道**：榜单主链路 = 轻量 fetch + detail-ssr（现状）；crawl4ai 部署 Cloud Run 作兜底（抓取异常时切换）；搜索主链路 = a_bogus 签名直调 search_book/v1，crawl4ai 兜底。
7. **a_bogus 移植**：以社区开源实现（mafqla/douyin-api abogus_new.py 或 ylcangel/douyin_sign）为基线移植为墨舟服务端模块（Node/TS），适配番茄参数；msToken 从页面/接口获取策略在实现中确定；签名失败必须 degraded=true 且不返回伪造结果。

## 后果
- 正向：扫榜页可回答「谁在涨、谁新进」；搜索数据真实且随扫榜积累变全；榜单 1:1 复刻在榜型维度达成。
- 负向：每日扫榜约 16 榜 × 20 书 ≈ 320+ 详情页请求（Cloud Run 出口流量与耗时可控但需预算意识）；a_bogus 属对抗性接口，字节改版可能导致签名失效——失效时降级 degraded 并告警，不静默伪造。
- 风险：crawl4ai 无头环境被风控（调研实测），兜底通道可靠性待生产验证。
