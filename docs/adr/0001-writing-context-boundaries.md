# ADR-0001：统一写作上下文边界与模型输入分层

日期：2026-08-12  
状态：Accepted for Gate 1；Gate 2 tickets review pending  
范围：墨舟 V1.2 独立写作对话与章节写作对话

## Context

墨舟已经上线，现有两条写作对话链的页面和 API 可以工作，但最终送给模型的输入没有统一契约。独立对话在没有注入资料时缺少写作助手身份；章节对话会保存本轮用户消息，却以空消息数组调用 provider；历史压缩返回的保留历史没有成为实际发送历史；旧测试 provider 只观察 system，无法证明 messages。

同时，作品资料、章节正文参考、章节对话历史和作者本轮请求属于不同语义层。把它们混在一个 system 文本中，会让参考资料替代用户意图，也会让章节正文参考被误认为对话历史。

## Decision

墨舟采用统一的写作上下文分层：

1. system 上下文依次表达身份基座、模式契约、归属后的作品上下文、章节参考、合法选区、风格、技能和压缩摘要。
2. messages 只承载按时间排序的历史对话与本轮请求；本轮请求必须是最后一条 user 消息并且只出现一次。
3. 独立会话若没有绑定作品，则没有作品上下文，RAG 不得隐式扩大到用户的其他作品。
4. 章节正文参考与章节对话历史分开；正文参考不替代章节对话消息。
5. provider 消费前保留一个统一的可观察输入 seam；测试读取真实 system/messages，生产只做脱敏结构观察。
6. 归属失败在 provider 调用之前终止请求，不产生跨作品或跨用户的模型输入。
7. 约束冲突时，system 的身份/安全/归属边界优先；作者本轮明确请求决定任务意图；已验证上下文约束事实；Style 与 Skill 约束执行方式但不能覆盖本轮请求。
8. `ConversationHistory` 只包含可重放的 user/assistant 对话事实；本轮请求按消息身份与历史分离后只追加一次。章节 assistant 的 `done/stopped/error` 是状态，不是新的 role。
9. 压缩失败或摘要不可用时采用 fail-open：不发送空摘要，发送完整有效历史与本轮请求，并将 `compression_applied` 记为 false。
10. 生产观察的 `payload_schema_version` 当前固定为 `v1`，只有字段语义不兼容时才递增。

## Consequences

- 身份基座和模式契约成为所有写作请求的稳定行为基础。
- 既有聊天 UI、SSE、消息落库、章节插入和冲突保护不需要因为本 ADR 重做。
- 测试必须断言最终 provider payload，而不能只断言数据库消息或 Mock 文本。
- 生产观察可以定位 payload 结构问题，但不会泄露正文、提示词、认证信息或作品资料。
- 本 ADR 不决定 embedding、Canon 编译器、多 Agent、工具调用或新的数据库表；这些仍在本轮范围之外。
