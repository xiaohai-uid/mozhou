# Electron 桌面迁移收口（阶段 1–2 复核后的九项）

> 本地规格文档（Local Spec Doc）。承载规格与决策，**不是执行状态**；执行状态一律看 GitHub 议题。
> 本文件由仓外审查产出（`.scratch/electron-migration/` 只留了晨报与调研，规格原稿在仓外目录）转录并本地化。
> 术语以 [`GLOSSARY.md`](../../GLOSSARY.md) 为准。

## Problem Statement

Electron 桌面壳与浏览器数据迁移工具已经存在，但**阶段 1–2 不能算验收通过**。隔离复现证实六条实质问题：旧计划覆盖新稿；导入后真实编辑器不恢复；多键失败留下部分状态；强杀被标成排空；已有密文但缺密钥仍生成新密钥；外来健康服务被接受。

这些不是风格问题，而是**报告与事实不一致**：程序会给出安全的结论，而事实未必安全。作者会因此丢稿、误以为数据已排空、或在不知情时把凭据弄成不可恢复。

## Solution

按九项规格收口，分四批推进，每批都可独立验收：

1. **修复批**：导入执行安全、导入后的工作台恢复、实例身份与跨代交接、停机结果与故障恢复、密钥与密文恢复护栏、正式安全路径与检查覆盖。
2. **打包批**：可复现 Windows 包与原生资源。
3. **验收批**：真实存量迁移、安装升级与回退。
4. **切换批**：发行入口切换与旧链路退役。

## User Stories

### 导入执行安全

1. 作为作者，我想在预览计划后继续写作，这样我的新稿不会被旧计划覆盖。
2. 作为作者，我想重复应用同一份计划时只生效一次，这样不会重复写入。
3. 作为作者，我想在预览中切书或换包时旧计划立即失效，这样不会把甲书的计划用到乙书。
4. 作为作者，我想让异步探针返回后核对代次，这样过期结果不会激活应用。
5. 作为作者，我想让包内同一目标槽出现多条时不被后项覆盖，这样内容不会丢。
6. 作为作者，我想在存储写入中途失败时拿到可恢复的办法，这样不会出现「写入零、数据已变」。
7. 作为作者，我想让探针读不到服务端时保守保留双份，这样不会凭读不到就覆盖。

### 导入后的工作台恢复

8. 作为作者，我想在导入完成后关掉面板就看见正确正文与候选，这样我不必刷新。
9. 作为作者，我想刷新后仍是同一现场，这样会话状态可复现。
10. 作为作者，我想让导入结果经真实会话装配生效，而不是只写缓存与成功计数。
11. 作为作者，我想让结构投影的读取合同被澄清，这样不会把「写进槽位」当成「结构已恢复」。
12. 作为作者，我想让迟到请求与切书负例被覆盖，这样切书不会串现场。

### 实例身份与跨代交接

13. 作为作者，我想让壳只连接正确的服务，这样不会以受信任来源载入无法核实归属的服务。
14. 作为作者，我想让实例锁缺失、损坏、不可读分别明确失败或给出恢复状态，这样不会「有锁才核对」。
15. 作为作者，我想让停止操作的成功以目标结束与资源释放为准，而不是端口可绑定。
16. 作为作者，我想让未知外来进程不被杀掉，这样不会误伤别人的程序。
17. 作为作者，我想让旧版实例落在备用端口时也能被识别，这样不会报告「没有在跑的实例」。

### 停机结果与故障恢复

18. 作为作者，我想区分排空完成、超时、强杀、崩溃与已退出，这样「安全退出」有可验证依据。
19. 作为作者，我想让子进程非零退出或收到结束信号不被改写成成功。
20. 作为作者，我想让未完成排空时退出码非零，这样异常不会返回普通成功。
21. 作为作者，我想让强杀中断后数据仍可恢复，这样承诺的是提交完整性而不是「保证排空」。

### 密钥与密文恢复护栏

22. 作为作者，我想让丢失密钥的恢复副本拒绝铸造替代密钥，这样既有凭据不会被静默毁掉。
23. 作为作者，我想让损坏的密钥与权限错误明确失败，这样不会静默重铸。
24. 作为作者，我想让正常副本沿用同一把密钥，这样重启后仍能解密原配置。

### 正式安全路径与检查覆盖

25. 作为作者，我想让正式启动不依赖降级开关，这样发布配置就是真实配置。
26. 作为作者，我想让桌面代码与关键行为被真实检查覆盖，而不是被排除在外。
27. 作为作者，我想让故意违规的负例被拒绝，这样门确实拦得住。
28. 作为作者，我想让自检记录子进程、端口与锁，并在超时或错误时也有界清理。

### 可复现 Windows 包

29. 作为作者，我想在没装开发仓库、Node 与包管理器的 Windows 上运行安装后的程序。
30. 作为作者，我想让原生能力（本地数据库、分词、最小推理）在安装包里真正可用。
31. 作为作者，我想让依赖与工具链版本被锁定，这样构建可复现。
32. 作为作者，我想让部署树不含真实数据与秘密，且不依赖外部目录链接。

### 存量迁移、安装升级与回退

33. 作为作者，我想让已安装旧版的用户迁入新包，且草稿与候选不丢。
34. 作为作者，我想让失败后仍能恢复旧工作，这样升级不冒险。
35. 作为作者，我想让卸载不删服务数据、密钥、配置与外部作品。
36. 作为作者，我想让格式不兼容时明确阻止回退，而不是留下半迁移状态。

### 发行入口切换与退役

37. 作为作者，我想让发行入口只有明确受支持的新路径。
38. 作为作者，我想让历史用户仍有可取得的恢复与迁移办法。
39. 作为作者，我想让旧链路在无人消费后才被删除，而不是先删后补。

## Implementation Decisions

- **唯一写入者**：导入执行安全、实例身份、停机结果、密钥护栏可由不同执行者并行，但共享入口（桌面主进程与打包服务端入口）与检查装配必须指定唯一写入者。
- **不重写全站存储**，不新增通用迁移框架，不自动把候选采纳为正文。
- **桌面代码不提供命令执行面**；技能与工具一律只存不执行。
- **不降低安全配置来制造通过**：降级诊断结果标为独立场景，不进入正式通过结论。
- **依赖边**：导入安全先于工作台恢复；密钥护栏与安全路径先于可复现包；前七项先于存量升级验收；存量升级通过后才切换发行入口。
- **真包验收前不切入口**：可复现包的配置设计可并行探索，但不得以打包成功提前关闭前六项。
- **平台边界**：本次只做 Windows 先行；不扩大多 Windows 登录会话支持。
- **提交、推送与发布各自独立授权**：本规格不授权其中任何一项。

## Testing Decisions

缝分两层，且**两层都不能互相代替**：

- **模块层与子进程层（保行为）**：停机结果、实例身份、密钥护栏用真实子进程与合成根验收；既有先例是 `scripts/verify-desktop-*.mjs` 三个脚本（当前分别 5 / 6 / 10 项通过）。导入执行安全与工作台恢复用模块层行为测试，既有先例是迁移目录下的行为测试。
- **真实装配层（保结论）**：导入后的工作台恢复必须在**真实桌面窗口**下跑完整旅程（关面板、继续输入、保存、刷新、切章）；存量迁移与升级回退必须在**真实安装包**上跑。组件级模拟测试不代替这两项。
- 好的测试只断言可观察行为与副作用：退出码、回读一致、拒绝与否、磁盘状态。不断言实现细节。
- 必须有的负例：越界与系统目录路径、外部路径未确认、原路径被占用时拒绝恢复、非 http(s) 与环回及私有地址、工具执行失败不编造结果、次数上限生效、旧计划与旧代次不得激活。
- 生成物与文档门同变更刷新，基线不自动更新。

## Out of Scope

- **签名证书与公开发行的信任缺口**：明确保留，不在本规格内解决。
- **会员与卡密链路**：不在本次范围。
- **无关的在途改动**：本规格不清理，也不把它们算进验收。
- **把提交等同发布**：提交、推送、发布是三个独立动作。
