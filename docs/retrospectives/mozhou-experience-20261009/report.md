# 墨舟失败案例与变更史复盘报告（2026-10-09）

## 结论先说

这一轮把墨舟近两周的**全部可访问记录**建成索引，从中还原出 29 个失败或反例案例，提炼为 24 条按触发条件组织的经验（`lessons.md`）。

最重要的发现不是某一条经验的内容，而是**经验本身没有生效的机制**：10 月 3 日已经记录过"安装包混入未提交代码"，10 月 7 日同类问题复发，10 月 8 日才补上脏工作区标记。经验写成了散文，没有绑定到任何机械检查点。

第二个发现是**验证的"通过"与用户实际路径之间存在系统性落差**：本地检查全绿但漏 lint（167 个错误）、CI 全绿但存在依赖环、30 个测试通过但生产未接线、同族 mock 分支漏生产闸。三个案例的共同结构是"验证覆盖了工具，没覆盖真实消费者"。

第三个发现偏负面：**本次文字回放未能证明经验条目会改变行动建议**。两组各 22 项标准，得分 21 与 22，唯一差异只有一项。这说明经验库当前形态的价值在于"提醒具体动作"，而不是"替代判断"。

## 2. 失败分类

29 个案例不是同一种"失败"。混为一类会导致经验写成空泛的"要更小心"。

### 2.1 产品故障（真实行为不符预期）

- **HC02** 恢复二次中断后"成功"却丢正典增量（追踪 930 字节/2 行 → 0）
- **HC03 / HC11** PID 存活被当作锁主人存活；`mtime` 超 30 秒强删可夺活锁
- **HC04** 单次 `writeSync` 不等于完整正文，短写恒返回 0 未失败
- **HC08** `await writeFile` 期间取消仍留下孤儿报告；双定时器错分 Timeout/Cancelled
- **HC14** 浏览器 GET query 与后端 body 输入通道错配，返回 400
- **HC15** 实现与策略都存在，但入口方法闸把 catalog GET 拦成 404
- **HC18** 子串扫描误报 TS 守卫/门禁；"上下文收据" 4 处全由上一轮自己引入
- **HC20** 按日期清理临时文件，删掉了会话开始前已存在的 4 个残留

### 2.2 验证缺口（测试通过但覆盖错了对象）

- **HC16** 本地封装漏 lint，act 跑出 167 个错误；修一次后新编排阶段 4 再漏同一门
- **HC17** CI 全绿但 HEAD 有环；madge 解析 2030 条边但跨包边为 0
- **HC19** 提交恢复测试多，但保存路径的 journal 输入形状不同，既有测试不能直接覆盖
- **HC05 / N03** 同族 mock 分支一处有生产闸一处漏闸；真实上游未验
- **N02** 27 项新测试 + 16 项回归通过，但生产未接线、图谱缺失
- **N04** `spawn ENOENT` 被判为套件红，实际是测试没跑
- **N05** 首轮全量测试遗漏共享消费方 DialogueStream
- **N08** 壳 8.44MB 与完整包 45MB 混为一谈；未列真实启动/退出杀进程

### 2.3 分析与判断错误（结论本身错了）

- **HC12** 第四轮修正报告把漏记方向与仍存在帧说反；后续实读旧 calls/frames 才纠正
- **HC13** 并发超时与 ENOBUFS 被直接归因机器负载，但**没有同负载对照**
- **HC10 / HC12** "9 次真实调用"混入误配置与未计数退避；最终为 10 个请求尝试，其中仅 2 条有足够公网端点身份依据
- **N09** esbuild Access denied 早期猜 SSD/权限，后续对照才支持外部扫描因素相关

### 2.4 范围与架构误判

- **HC09** 两个约 1043 行的契约副本各自为准；进程树工具无生产消费者且有终止等待缺陷
- **HC01** 散文提醒未进入机械入口 → 同类问题四天后复发（**本轮最重要的案例**）
- **N01** `RENAME_NOREPLACE` 不支持时 `EINVAL`，草案存在但正式发布未发生
- **N12** 清理 CLAUDE 指针后工具再次追加

### 2.5 成功反例（必须保留，防止过度归因）

- **HC07** 迟到生成只进入 `draft_candidates.jsonl`，第 1、2 章正文均不变。这是**成功隔离**，不是正文污染事故。

分类的意义：2.1 需要改实现，2.2 需要改验证方法，2.3 需要改分析方法，2.4 需要改范围判断，2.5 需要防止过度修正。若把 2.3 归为 2.1，就会去"修"一个没有 bug 的地方。

## 3. 经验提炼结果

`lessons.md` 共 24 条（L01–L24）。每条包含：触发条件、失败机制、具体动作与验收、例外与失效条件、现有防护与剩余缺口。

### 跨案例反复出现的结构

把 29 个案例放在一起看，**失败不是随机的**，反复出现四类结构：

**结构一：验证覆盖了工具，没覆盖真实消费者。** HC14/HC15（GET vs body、方法闸）、HC16/HC17（本地封装 vs workflow、相对环 vs 跨包环）、HC19（共用函数 vs 调用方输入形状）、N05（直接调用方 vs 共享消费方）、HC05（同族分支）。这是墨舟出现次数最多的失败结构，也是本库中条目最密集的地方（L02、L06、L08、L09、L21）。

**结构二：间接信号被当成因果证据。** HC03/HC11（PID 存活、文件年龄 → 所有权）、HC13（并发相关性 → 机器负载根因）、HC10/HC12（provider 字符串 → 公网调用）、HC20（文件日期 → 本次创建归属）。对策统一为"绑定身份与归属，不用间接信号代替"（L04、L13、L14、L16）。

**结构三：状态描述没有绑定机器可判定的结果。** HC06（CAS 通过 → 副作用未重复）、HC15（下层存在 → 路由可达）、HC10（"9 次调用" → 10 次尝试）、N13（BLOCKED 却 exit 0）、N04（没跑 → 判红）。对策是回读实际数据面、绑定退出码、区分"未运行"（L03、L11、L12、L13）。

**结构四：经验写成散文，没有绑定机械入口。** 只有 HC01 一例，但它是**唯一一个"已知发生过仍然复发"**的案例，因此权重最高（L01、L24）。

### 与既有防护的关系

24 条中，**18 条已有对应的历史修复或防护**；本库的作用是"在触发时提醒去用那些防护"，不是重新发明。真正**没有**对应防护的只有 L24 本身——它指向的是机制缺失，而非具体实现缺陷。

### 未覆盖范围（库内不给建议）

真实付费上游行为、hosted 环境（CI/鉴权/部署）、跨登录会话与网络共享锁、物理断电恢复、浏览器真实点击与视觉、IME/Redo、动态 import 解析边、换机器或换杀软的构建稳定性、本轮之后的任何变更。

## 4. 验证经验是否有用

### 方法

按时间顺序切分：用**截至 2026-10-04** 的案例提炼经验草案，再把**较晚**的情境（T5 的保存恢复、T6 的锁范围，以及两个不适用场景 N1/N2）作为检验题。两个独立代理收到**相同**场景材料，一个额外收到经验草案（E1–E8），**都看不到后续处理结果**。评分标准 22 项二元指标在输出前冻结，由主代理逐项阅读判定，不用关键词自动评分。逐项判定与证据句保存在 `casebook.jsonl`（`record_type=replay_score`，44 条）。

### 结果

| 场景 | 无经验草案 | 有经验草案 |
|---|---|---|
| T1 交付构建产物 | 3/3 | 3/3 |
| T2 浏览器 GET 下载 | 3/3 | 3/3 |
| T3 await 期间取消 | **2/3** | 3/3 |
| T4 本地绿 vs workflow | 3/3 | 3/3 |
| T5 保存恢复窗口 | 3/3 | 3/3 |
| T6 锁支持范围 | 3/3 | 3/3 |
| N1 不适用（文档错字） | 2/2 | 2/2 |

| **合计** | **21/22** | **22/22** |

唯一差异在 T3 的"超时与取消生命周期、错误分类、副作用结束后重新核对身份"：无经验组未提错误/终帧分类，有经验组明确写出"释放阻塞后检查迟到完成、错误和最终响应是否重新核对身份与取消状态"，并在边界声明中区分下游丢弃／资源回收／上游停止三种保证。

不适用场景（N1、N2）两组都没有被经验条目带偏——没有出现无关全量测试、图谱调用或付费验收的建议。这条负向结果与正向差异同样重要。

### 这次回放不能证明什么

1. **每条件只跑一次**，无随机重复，无统计效力。
2. **整理者已知后续处理结果**，不是严格的前瞻盲法。
3. 合成文字回放，**未执行任何产品操作**；它比较的是建议内容，不是行为。
4. **不能证明经验条目会降低未来失败率**，也不能证明经验会自动生效。

### 对本轮工作方式本身的反例

值得记录的是：**这次回放中，"无经验"的一组也给出了相当完整的检查建议**（7/8 场景满分）。这本身削弱了"必须提供经验才能避免错误"的假设。更符合证据的结论是——经验库的价值在于**把"该验证什么"落到具体动作与验收标准**（例如"回读正文/revision/候选/操作状态"而不是"检查隔离"），而不在于提供判断力。L01/L03/L06/L08/L11 因此写的是动作，不是原则。

- 13 个对话线程为筛选后审阅，非逐条全文核验；其它客户端与通用 cwd 会话可能缺失。
- HC06 的历史文档与源码链**未闭合**——本轮未重新核对接口源码，**本次未过图谱门禁**。
- 图谱索引在采集时已刷新（原索引停在 10 月 7 日），但**当前图谱不能作为历史版本的运行证明**。
- 6 条历史调用帧不可恢复，仅 10:23 帧仍在（HC10/HC12）。

**经验层**

- 24 条中 18 条的历史修复**本轮均未在产品上复测**。"历史结果"指当时的记录，不是当前状态。
- 多条经验指向同一缺口（真实付费上游未验证出现 5 次、hosted 未验出现 4 次、浏览器路径未验出现 3 次）。这些是**跨案例的系统性缺口**，不是单条经验的缺陷。
- 回放未能证明经验改变行动建议（21 vs 22）。若要获得更强证据，需要多次重复 + 前瞻盲法 + 真实任务，而非更多条目。
