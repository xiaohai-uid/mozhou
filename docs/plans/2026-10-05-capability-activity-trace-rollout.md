## 本次直接交付

针对 `packages/pipeline/src/review-step.ts` 的真实章节审查，新增 `apps/web/shared/reviewCapability.schema.ts` 与自动执行的契约测试。契约覆盖完整质量策略（含语义规则）、正文快照与版本、失败模式、审查者绑定、机械检查选项、审查结果和失败。暂不修改生产路由/会话接线。

现有入口还负责报告落盘、金句收割、反例吸收和 session 推进。它们属于主程序，不通过 JSON 传递书根、session、回调或凭据。语义审查提供方按 reviewer 配置在执行端解析；未配置或异常仍保留现有 `unknown → refused` 行为，不允许用通过结果掩盖不可用。

## 清晰的输入输出

- 输入：schemaVersion、requestId、正文快照（chapterIndex/revision/body/contentHash）、receiptId、已合并 policy、reviewer、failurePatterns，以及可选 actionBeatParagraphs/mechanicalOptions。
- 输出：同版本与 requestId、质量报告与机械检查结果，或结构化错误。审查 verdict 与传输是否成功分开；refused 是合法的审查结论，不能当成 PASS。
- Set 改用非负整数数组；结果绑定章号、revision、正文哈希、编译凭证、规则摘要及 reviewer。结果与请求不一致时拒绝，不能用于主程序的报告落盘/推进。
- 类型与运行时校验同源于本文件中的 JSON Schema。它可在浏览器/Node 使用，不导入 Node API 或墨舟内部实例。
- 共享校验检查字段、结论及请求/结果关联；它不计算 SHA-256，也不验证编译凭证真实存在。主程序装配时须从真实 draft/编译结果生成锚点，执行端重新计算正文与规则摘要，禁止仅凭一个合法格式的哈希字符串声明新鲜。
- 不传 timeout/attempt/span 等尚未实施的生命周期字段；取消/超时行为留到下一步真实异步接线验证。
