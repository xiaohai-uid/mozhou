## 3. 浏览器「停止生成」入口 —— 未实现、未验收

- 现状：全仓**没有任何** `/api/draft.cancel` 的调用方。只有路由定义（`pipelineRoutes.ts:684`）、
  路由策略、租户测试、fullJourney 测试与 CONTRACTS.md 提到它。
- 浏览器侧唯一的取消是 `DialogueStream.tsx:135,140` 的 `reader.cancel()`，
  它只是断开流，**不是**面向作者的「停止」按钮。
- 本轮**没有**实现它（按指令留给下一张工单），也**没有**对它做任何验收。
- 要验它需要：先实现 UI 入口 + 契约测试 + 一次真实浏览器端到端点击验证。

## 4. `pnpm test` 的 flake 归因 —— 未独立证明

- 观测到的事实：合并跑 `pnpm test` 时每次各有 1 个失败（`memoRoutes.test.ts` 超时、
  `pipelineRoutes.tierRoute.test.ts` 报 `connect ENOBUFS`）；分开单独跑则全绿。
- **未证明**的部分：这两个失败是否**由并发负载引起**。本轮没有做「同负载对照 / 不同负载对照」实验，
  也没有采集 CPU/句柄/连接数等负载指标。**不得**据此断言「不是产品缺陷」。
- 要证明它需要：受控负载实验（同用例集 × {串行, 并发 N}）+ 失败时刻的资源采样。

## 6. 额度机制本身的边界

已验证：跨进程共享、并发不超发、重启不重置、异常/429/取消不退款、非法预算与损坏账本 fail-closed、原子写。

**未验证**：

- 锁的**陈旧回收**（staleMs 30s）只在离线测试里间接走过，**没有**构造「进程被 kill 后锁残留超过 30s」的真实场景。
- `HARD_CEILING = 64` 的上界行为**未**做端到端运行验证（只验证了负数与字符串被拒）。
- 账本**只增不减**：没有实现也没有验证「额度被误占用后的人工校正」流程。
- 锁在**网络盘 / 非本地盘**上的行为未验证（本机为本地 NTFS）。
