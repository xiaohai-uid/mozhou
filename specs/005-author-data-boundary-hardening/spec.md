# Feature Specification: 作者数据完整性与出站边界加固

**Feature Branch**: `005-author-data-boundary-hardening`

**Created**: 2026-10-12

**Status**: Implemented（规格为**事后记录**：实现先于本规格，见 Assumptions）

**Input**: User description: "按《墨舟具体修改方案》修三个边界（采纳并发与恢复、账本追加失败、出站取消与 DNS 连接绑定），并按独立验收页 S1–S4 / T1–T3 返工；规格先行工具链用于把该改动集落成仓内规格产物。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 作者点「采纳」后正文只生效一次，中断后能查到同一结果 (Priority: P1)

作者在候选稿上点「采纳进正文」。网络可能丢响应、进程可能中途重启、同一请求可能被重试。作者期望：无论重试多少次，正文只被写一次、版本只涨一次，且事后能查到这次采纳的结果与它关联的任务。

**Why this priority**: 这是作者作品的写入路径。重复写入或版本漂移会直接损坏作者已定稿的内容，属不可接受的数据事故；其余两条故事都是它的补充面。

**Independent Test**: 在隔离书根上对同一候选连续提交同一采纳请求，观察正文版本增长次数与返回结果；再制造「已落盘但结果未记录」的中断现场后重试，观察结果是否可查。

**Acceptance Scenarios**:

1. **Given** 候选已就绪且作者已成功采纳一次，**When** 同一请求再次提交，**Then** 正文版本不再增长，返回与首次一致的正文版本与内容指纹。
2. **Given** 正文已落盘但采纳结果尚未记录时进程终止，**When** 重启后提交同一请求，**Then** 正文版本只增长一次，且该操作的结果与任务关联均可查到。
3. **Given** 某主体已用某操作标识完成一次采纳，**When** 另一主体提交省略操作标识的请求，**Then** 在任何正文/候选/记录变更之前被明确拒绝。
4. **Given** 采纳记录缺少原始操作身份（历史记录），**When** 请求携带新的操作标识，**Then** 拒绝把该请求绑定到该记录上。
5. **Given** 正文在采纳过程中被外部编辑，**When** 提交采纳，**Then** 明确报告冲突并保留双方内容，不静默覆盖。

### User Story 2 - 生成中取消或切章，旧回调不污染新现场 (Priority: P2)

作者在生成过程中按「停止」或切换章节。已经离开的那次生成，其迟到的内容与回调不得写进当前现场，也不得把被取消的内容当作成功结果。

**Why this priority**: 取消是作者控制成本的常规动作；若取消后仍有内容落盘或仍向上游付费发请求，作者会得到自己没要的内容并产生不可预期的费用。

**Independent Test**: 用确定性的排队屏障让某次写入排队，期间取消，再放行；观察候选内容字节与最终状态。另在单次响应块内含多条内容时，取走第一条后取消，观察第二条是否产出。

**Acceptance Scenarios**:

1. **Given** 候选写入正在排队等待，**When** 等待期间作者取消，**Then** 候选内容字节零变化，且不出现成功状态。
2. **Given** 上游响应块中已缓冲多条内容，**When** 取走第一条后取消，**Then** 其余内容不再产出。
3. **Given** 生成在启动前已取消，**When** 生成流程启动，**Then** 不向上游发起任何请求。
4. **Given** 解析目标地址期间取消，**When** 解析返回，**Then** 不向上游发起请求。
5. **Given** 消费方提前停止读取，**When** 生成终止，**Then** 上游连接被释放。

---

### User Story 3 - 出站请求只连到经过校验的目标，并与既有客户端行为兼容 (Priority: P3)

墨舟会代表作者访问上游模型、检索服务与网页。作者与部署者期望：这些请求不会因为域名解析被操纵而连到内网或本机；同时读取上游内容的能力不因安全加固而退化。

**Why this priority**: 这是安全边界与兼容性边界。它不直接改动作者作品，但决定了整条出站链路是否可被滥用，以及加固是否会把正常上游读坏。

**Independent Test**: 用真实回环服务与注入式解析夹具，分别验证：私网解析被拒且零请求、连接使用已验证地址、压缩响应可读、取消与远端断开得到不同错误类别。

**Acceptance Scenarios**:

1. **Given** 目标域名的解析结果包含私有/环回/保留地址，**When** 发起请求，**Then** 整体拒绝且不产生任何出站请求。
2. **Given** 校验通过后解析答案发生变化，**When** 建立连接，**Then** 连接仍只使用已验证的地址，且域名身份（Host 与证书校验对象）保持为原域名。
3. **Given** 上游以压缩编码返回内容，**When** 读取正文或流式内容，**Then** 得到与未压缩时一致的文本；未知编码则显式失败，不把压缩字节当正文。
4. **Given** 请求在读取响应体期间被主动取消，**When** 观察错误类别，**Then** 归类为「已取消」；若为远端自行断开，**Then** 归类为网络失败而非用户取消。
5. **Given** 部署者显式授权本机模型端点，**When** 请求该端点，**Then** 既有授权行为不变。

---

### Edge Cases

- 账本尾部出现无法证明安全的半行（部分写入）后触发恢复：必须保持「停止发布」并保留原件，不得跳过坏行宣称恢复成功。
- 恢复过程中读取账本失败：同样保持停止，不得因读取异常而解除保护。
- 采纳意图记录为历史版本（缺少原始操作身份）时，兼容路径与拒绝路径必须分别明确，不留静默旁路。
- 上游返回未支持的压缩编码：显式失败。
- 部署者授权的本机端点不参与公网地址校验。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 采纳入口 MUST 与同书其他正文写入共用同一互斥，使同书并发写入串行化。
- **FR-002**: 采纳 MUST 在产生任何盘面副作用之前完成操作身份校验：操作标识、主体、书、操作类型、请求摘要五项 MUST 全部一致——可由一处或多处检查共同保证（不要求单点比较）。
- **FR-003**: 采纳意图 MUST 持久化原始操作身份与请求摘要；读取端 MUST 同时接受新旧两种记录格式。
- **FR-004**: 采纳意图缺少原始操作身份时，系统 MUST 拒绝把携带新操作标识的请求绑定到该记录。
- **FR-005**: 采纳的正常完成、幂等回放、崩溃恢复三条出口 MUST 共用同一结果补全逻辑，且 MUST 在结果记录与任务关联补齐后才返回成功。
- **FR-006**: 事件账本发布 MUST 在校验与状态计算之后、追加成功之后才提交内存配对状态；追加失败时内存状态 MUST 保持不变。
- **FR-007**: 追加失败后（结果不明）实例 MUST 停止继续发布，直到调用方按账本核对并显式恢复。
- **FR-008**: 恢复入口 MUST 在解除停止之前核对账本物理完整性；发现半行或读取失败时 MUST 保持停止并保留原件。
- **FR-009**: 候选内容的读-改-写 MUST 在书级互斥的短临界区内完成；模型等待 MUST 留在临界区之外。
- **FR-010**: 候选写入 MUST 在取得互斥之后、落盘之前复查取消状态；等待期间被取消时 MUST 丢弃待写内容并按「未完成」结算。
- **FR-011**: 出站请求 MUST 在校验目标之后、发起请求之前复查取消状态；启动前或解析期间取消时 MUST 不发起请求。
- **FR-012**: 出站连接 MUST 使用与校验同源的解析结果，并 MUST 保持原域名的 Host 与证书校验对象。
- **FR-013**: 出站响应体 MUST 按响应声明的内容编码解码，流式读取与整体读取 MUST 走同一条解码路径；未支持的编码 MUST 显式失败而非把原始字节当正文。
- **FR-014**: 出站请求 MUST 声明与既有实现一致的压缩协商，避免协商行为改变。
- **FR-015**: 取消导致的读取失败 MUST 保留「已取消」分类；非取消的远端断开 MUST 保持网络失败分类。
- **FR-016**: 取消生效后 MUST 不再产出已缓冲的内容，并 MUST 释放上游连接。
- **FR-017**: 配置/环境变量提供的出站端点 MUST 与用户输入端点走同一校验与绑定门。
- **FR-018**: 本轮 MUST 不新增外部依赖、不迁库、不放宽既有安全门。除本规格明示的边界扩展（FR-002 身份校验收紧、FR-003 意图格式 v2、FR-004 缺原身份拒绝、FR-005 结果补全共用、FR-008 账本恢复完整性、FR-013 出站解码）外，MUST 不改变作者数据与既有接口的契约。

### Key Entities *(include if feature involves data)*

- **采纳意图记录 (Accept Intent)**: 一次采纳操作的持久意图，含格式版本、候选身份、幂等键、写入前后指纹、状态，以及原始操作身份（操作标识、主体、请求摘要、可选任务）。
- **操作结果记录 (Operation Record)**: 一次已生效写入的结果与作用域，供状态查询与回放；本轮补齐了「结果记录已写但任务关联未写」的窗口。
- **候选草稿 (Candidate Draft)**: 尚未采纳的生成产物；其内容与状态只经采纳进入正文。
- **事件账本 (Event Ledger)**: 只追加的领域/任务事件日志；本轮为其恢复入口增加物理完整性契约（半行即不可恢复）。
- **出站目标 (Outbound Target)**: 一次出站请求的地址身份——原域名与其已验证解析地址集合。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 采纳请求重试任意次数，正文版本增长次数恒为 1。
- **SC-002**: 「结果记录已写、任务关联未写」的窗口重启后重试，任务关联恢复率 100%，正文版本不再增长。
- **SC-003**: 主体不匹配或操作标识缺失的采纳请求，在任何数据变更前被拒绝的比例为 100%。
- **SC-004**: 等待写入互斥期间被取消的生成，候选内容变化字节数为 0，且最终状态不为成功。
- **SC-005**: 已取消的生成向上游发起的请求数为 0。
- **SC-006**: 解析结果含私网/环回/保留地址的出站请求，拒绝率 100% 且出站请求数为 0。
- **SC-007**: 压缩响应的读取结果与同一内容的未压缩响应逐字一致。
- **SC-008**: 每个本轮修复窗口都有在修复前实现上必然失败的回归用例；既有全部回归用例保持通过。
- **SC-009**: 类型检查、静态检查、构建与依赖环检查全部无错误（环数为 0）。

## Assumptions

- **本轮为事后记录**：实现先于本规格。规格按最终行为回填，用于把该改动集纳入仓内规格产物并作为后续验收基线；它不声称曾指导实现。
- 工程宪法取 `AGENTS.md` §1–§8（UVSD Protocol v2.2.1 Final）。`.specify/memory/constitution.md` 自述为未实例化的上游模板且 spec-kit 已按 ADR-0031 降级为产物目录，故本规格不引用其 Constitution Check 门。
- 作者数据契约不变：本轮只补边界（互斥、身份、结果补全、账本完整性、取消、连接绑定），不新增功能、不迁移数据。
- 采纳意图的格式扩展向后兼容：读取端同时接受新旧记录；老客户端（从不携带操作标识）的既有回放路径不变。
- 以下不在本轮验收范围（保持未验证）：真实两进程争用、真实进程中断恢复、真实模型调用、真实 DNS rebinding 攻击、修复后的完整作者旅程。
- 上游压缩协商按既有实现的默认集合声明；未知编码按失败处理。
- 本规格不含实现细节；文件、函数与测试的对应关系记录在 `plan.md` 与 `tasks.md`。
