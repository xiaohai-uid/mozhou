# 墨舟产品形态设计决策（2026-08-10，grill-with-docs 定案）

> 触发：抽卡模式并入写作对话后，产品视角审查发现全站同类"流程割裂"问题 —— 工具产出无法回流写作主流程。5 项决策全部按 agent 推荐定案。

## 核心洞察
墨舟的真实主流程是【写作对话】。所有工具（蒸馏/拆解/搜索/技能/抽卡/书架）都是产线，不是孤岛。
病灶：功能独立成页 → 产出困在自己页面 → 用户需复制粘贴/跳页搬运。

## 决策

### R1 — 回流架构形态：混合（C）
- 蒸馏/拆解：完整操作留在独立页（大文本区/章节选择），产出加**"应用到对话"按钮**回流
- 轻量操作（搜索引用、技能启用）：进 **chat 工具条**内联
- 抽卡：已内联（4c7621f）

### R2 — 产物落位：按类型分流（C）
- **上下文注入（system，持续生效）**：风格指南、技能、设定 → 影响后续所有回复
- **消息插入（一次性）**：拆解结果、搜索引用、抽卡候选 → 作为对话内容

### R3 — 会话↔作品绑定：现在接（A）
- chat 顶部加"当前作品"选择器，RAG 注入只检索该作品设定（写 A 书不混 B 书）
- ⚠️ **事实修正**：`sessions` 表实际没有 `novel_id` 字段（schema 注释是计划不是现实），需要 migration 0004 加列
- 切片：migration 0004 → chat 顶部选择器 → RAG 按作品过滤

### R4 — 蒸馏/技能应用形态：chat 内选择器（A）
- 对话顶部胶囊行：**风格**（单选：无/已应用 ×N）、**技能**（多选叠加）
- 风格同时只生效一个（一种文风），技能可多选
- 注入位置：system 提示（R2 上下文类）

### R5 — 书源/书架打通：归工单 08（A）
- 导入→书架→拆解联动是 08 书源引擎核心内容，现在只保证 UI 形态正确
- 不做简化版，避免重复建设

## 实现顺序
1. 切片 1：sessions.novel_id（migration 0004 + schema）—— 会话知道在写哪本书
2. 切片 2：chat 顶部作品选择器（UI）
3. 切片 3：RAG 按作品过滤（rag.ts 加 novelId 参数）
4. 切片 4：chat 风格/技能选择器胶囊（R4）
5. 切片 5：蒸馏页"应用到对话"按钮 + 拆解页"发送到对话"按钮（R1/R2）
6. 工单 08 时：书源导入→书架→拆解联动（R5）

## 契约影响
- 第 2 节（写作对话）：会话结构新增 `novelId`（可空）；chat 请求可选带 `novelId`
- 第 7 节（抽卡）：已标记 dryRun 归工单 10
