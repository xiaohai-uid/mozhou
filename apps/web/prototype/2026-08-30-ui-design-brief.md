# 墨舟 Novel OS 2.0 · UI 设计任务书（交给设计 AI / Codex）

> 2026-08-30。编写者：ZCode 会话（负责墨舟 Novel OS 主线工程）。任务：由你（设计 AI）产出**下一代 UI 设计原型**。
> 用户背景：独立网文作者，中文产品。对前几版原型的裁决：v1"很烂"、v2"不太行，不够高级，要结合 WebGL 与高级设计语言"。**高级感是本次核心验收**。

## 1. 交付物（先读这节）

- **单文件 HTML 原型**，放 `apps/web/prototype/codex-ui-<你的方案名>.html`。零依赖、零构建、双击可开（file://）；禁止 CDN 字体/库；WebGL 手写原生。
- 多方案时用 `?variant=` URL 参数 + 底部浮动切换条（‹ › 按钮 + ←/→ 方向键，输入框聚焦时不拦截），右上角固定 "PROTOTYPE" 斜角角标。
- 静态 mock 数据只读展示（可复用本目录现有原型里的数据结构）；不接任何真实后端、不做持久化。
- **必须覆盖的界面密度**（用户明确否决过"只摆几个面板"的贫瘠版）：
  1. 工作台：写作对话（AI 先问 + 气泡流 + 输入区）+ 右栏阶段轨/技能胶囊 + 四个新面板（质量门 / Story Brain / Context Receipt 装配看板 / 变更矩阵，内容结构见 §4）；
  2. 完整功能导航（17 项五组，§3.1）以你选的 IA 方式全部可见可达；
  3. 技能面可见（内置 6 / 广场 3 / oh-story 13 / 我的 4 + 风格单选胶囊行）；
  4. Wizard 五步入口形态（首次建书引导）。
- 随原型附 200-400 字设计决策说明（写入文件头注释即可）：宏观 IA 选择理由 + 设计语言要点。

## 2. 产品全貌（应用整体是什么）

**墨舟（MoZhou）= 个人小说写作操作系统**，服务中文网文作者的全流程：找题材（扫榜/书源）→ 拆解学习（小说拆解/风格蒸馏）→ 开书（Wizard 五步）→ 逐章写作（AI 对话 + 十步管线）→ 质量把关（文学质量门 + 确定性连续性门）→ 正典管理（提案确认/变更影响）→ 飞轮学习（偏好/风格/任务模型三学习者，沉睡中）。

**核心写作循环**（UI 要让这个循环可感知）：
与 AI 写作对话（"墨舟先问"：AI 先提问、作者先作答）→ Context Compiler 装配上下文（产出 **Context Receipt**，逐 token 装配分解可检视、可确定性重算、可续跑）→ 草稿流式生成 → 文学质量门审查（blocking 失败阻止前进，显式回炉 ≤2 次）→ 确定性 Continuity Gate → 正典提案逐条确认（Proposal Port）→ 提交正典。设定改动 → **变更矩阵**（行=遍历/列=受影响章，红=需重写）→ 幂等重跑消解。

**技术两条线**（设计目标是前者）：
- **Novel OS 主线**：`apps/web`（Vite+React18+TS，单页）+ `packages/*`（kernel/data-plane/pipeline/quality-engine/runtime 等纯 TS 包）。样式决策已定：引入 Tailwind v4。
- legacy 应用线：`app/`（Next.js 16 + Tailwind v4 + PostgreSQL，**已冻结为遗留面**，只作像素级视觉参考——它是用户"完胜"认可的旧版，跑在 localhost:3001）。

**关键领域词**（CONTEXT.md 已冻结，UI 文案必须用规范词）：Context Receipt（**禁止**叫 "Context Viewer"，中文"装配看板"）、ChapterProductionSession（章节生产会话，十步管线）、QualityReviewReport（质量门报告）、Story Brain（实体卡/大纲树/事实列表）、变更矩阵（Change Matrix）、提案确认面（Proposal Port）、能力注册表（Capability Registry）。认知层级标签：canon（正典）/ suspect（怀疑）/ belief（信念）——事实列表里要区分呈现。

### 3.2 技能面

- **技能胶囊行**（写作输入区上方）：多选开关，选中集随请求注入。内置执行器 6：故事基座、质量门（常驻注入，不进胶囊）+ 章节规划、读者题材、叙事风格（开关型进胶囊）+ 自定义提示。样例胶囊：续写/对白打磨/悬念调度/场景氛围/一致性自查。
- **风格胶囊行**：单选（"无"是显式选项），数据源 = 蒸馏产出的风格档。
- 广场技能：去 AI 味 / 人物小传 / 信息差设计。

## 4. 已锁定决策（不可推翻，只能遵守）

1. **品牌「夜墨编辑工作室」token 逐值**（源：`app/app/globals.css:4-23`，可加衍生透明度/渐变，**基色不可改**）：
   `--background:#0b0a0f` `--foreground:#f4f1fa` `--accent:#8b78ff` `--accent-strong:#9d8eff` `--accent-soft:rgba(139,120,255,.12)`；表面五级 `--surface:#15131a` `--surface-2:#282330` `--surface-3:#1d1923` `--surface-raised:#211c29` `--surface-sunken:#100e14`；`--hairline:rgba(244,241,250,.1)` `--hairline-strong:…16`；`--text-muted:#aba4b8` `--text-faint:#7c7487`；`--danger:#f28b9b` `--success:#80d6b0` `--warning:#e4b875`；圆角 0.5/0.75/1rem；中文黑体栈（PingFang SC/微软雅黑）+ mono。
2. **深色唯一主题**；**桌面优先**（移动端不进本期验收，但 1280px 下不许布局崩坏）。
3. 样式底座 = Tailwind v4 + 上述 CSS 变量（原型里纯 CSS 即可，落地才用 Tailwind）。
4. **Wizard 五步仅首次建书**（建书→世界观→大纲→首章→连写），之后常驻工作台，可重放。
5. 单页无路由库：视图状态 + localStorage 记忆（原型里可忽略持久化）。
6. 阶段轨词表 = **管线十步**：prepare / compile / draft / review / extract / continuity / proposal / commit（原型展示 8 步即可），**不是** legacy chat 的 7 相位。
7. 未接入的能力**显式标注 unavailable**（如质量门里的 Gate 3 横幅），禁止静默假装可用。
8. 中文 UI 文案；正文可读性优先于装饰。

## 5. 开放给你裁决的面（这是你的设计价值所在）

1. **宏观信息架构**——三个已探索候选（原型见 §6），可选其一、混搭、或提出全新第四方案，需说明理由：
   - A 全功能单壳：17+ 功能平级常驻左栏五组，工作台只是其中一项；
   - B 专注工作台 + 功能抽屉：工作台独占全屏（legacy 双壳原味），☰ 抽屉承载全部功能，右栏检视 tab 塔承载新面板；
   - C 指挥台 + 命令面板：仪表盘为家（继续写作/质量门/任务/工具/资源卡片），⌘K 命令面板直达一切功能与技能。
2. **"高级"如何落地**（用户核心诉求，前两版都栽在这里）：
   - WebGL 的用法与克制度（墨流/粒子/雾/光斑？动多静多？占多大画面？）；
   - 动效体系（入场/悬浮/状态迁移/呼吸）；排印体系（衬线×黑体混排？字号阶？字距）；
   - 材质（玻璃拟态/噪点颗粒/晕影/辉光的配比）。
   参考：现有 `ui-baseline-premium.html` 已做了一版"WebGL 墨流 + 玻璃 + 衬线"，用户尚未认可——**你要做得明显更高级，或在它基础上指出并修正不够高级的原因**。

## 7. 硬约束

- **只读区**：`apps/web/src/**`、`packages/**`、`app/**`、`docs/**` 一律不许修改；你只新增 `apps/web/prototype/codex-ui-*.html`。

- 完成后输出：生成文件的绝对路径 + 设计决策说明（复述文件头注释即可）。

## 8. 用户会怎么验收（评分口径）

1. **高级感**（第一权重）：是否一眼"这是花钱设计的产品"——质感、光、动效、排印的整体协调；
2. **功能面完整**：17 功能+技能面+四面板+Wizard 全部有位置，不贫瘠；
3. **品牌保真**：夜墨紫 + 近黑底 + 发丝线，一眼还是墨舟；
4. **信息架构**：核心写作循环（对话→装配→草稿→质量门→正典→变更）在 UI 上可读；
5. 工程可用性：设计语言能翻译成 Tailwind v4 + CSS 变量（别用无法落地的效果）。
