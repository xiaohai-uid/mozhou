## 4. 证据强度分级（由弱到强）

| 级别 | 名称 | 含义 | 允许的表述 |
|---|---|---|---|
| E1 | 静态检查 | 读文件、grep、git show、AST/图谱查询 | 「代码中存在」 |
| E2 | 代码推演 | 基于 E1 推断运行行为，**未实际运行** | 「按代码推演应当…」+ 必须写明未运行 |
| E3 | mock 测试 | 跑 vitest/脚本，mock 数据、假 provider、离线 | 「在 mock 条件下通过」 |
| E4 | 真实本地集成 | 真实本地进程/真实 SQLite/真实 HTTP 本机打通，无外部供应商 | 「本地真实打通」+ 写明触达的真实组件 |
| E5 | 真实浏览器或桌面 | 真实浏览器/桌面程序加载并交互 | 「真实 UI 路径通过」+ 写明版本与数据目录 |
| E6 | 真实供应商调用 | 真实模型/支付/第三方 API | 默认 `NOT RUN`（不在授权内） |
| E7 | 系统级故障实验 | 注入故障、断网、断依赖、杀进程等 | 需单独授权；本次默认 `NOT RUN` |

**禁止用低级别冒充高级别。** 具体地（对齐主契约）：

- 测试通过 ≠ 用户路径验收；构建成功 ≠ 运行正确；测试数量多 ≠ 覆盖到。
- `detect_changes` 报 `critical` 风险 ≠ 已发现缺陷；它只说明拓扑面大。
- 图谱通过 ≠ 图谱覆盖（见 §7）。
- 不得用 grep 冒充图谱分析；也不得用图谱替代读源码。

## 5. 未知项写法（强制三段式）

任何无法确证的事实，按下列格式写，**禁止留空、禁止猜测、禁止用「应该」「大概」**：

```
未验证。缺什么证据：<具体证据类型与位置>。最小补证方法：<一条可在不破坏只读边界下执行的具体动作>。
```

正例：
> 未验证。缺什么证据：`pipelineRoutes.advance` 在生产模式下是否真的拒绝跨书推进——需要一次真实 HTTP 调用 + 真实 SQLite。最小补证方法：用 `MOZHOU_DATA_ROOT` 指向临时空目录起一份服务，发一次 `POST /api/pipeline/advance`，检查返回码。

反例（禁止）：
> 看起来是安全的 / 大概没问题 / 应该是这样 / 未发现问题（等于断言不存在）

## 6. 判定词定义（全组统一，禁止自造）

| 判定词 | 定义 | 最低证据级别 |
|---|---|---|
| `PASS` | 在被审计路径上实际验证过，行为符合声明 | E3（涉及运行时行为时需 E4） |
| `PARTIAL` | 主路径验证通过，但存在已命名的未覆盖分支/边界/平台 | E3 + 写明未覆盖范围 |
| `FAIL` | 实际验证到与声明不符，或违反已声明的不变式 | E3（结论需可复现步骤） |
| `UNVERIFIED` | 未获得足以判定的证据 | 无（必须附 §5 三段式） |
| `BLOCKED` | 需要的能力/授权/前置条件不可得，无法继续 | 无（必须写明阻塞对象与已尝试步骤） |
| `NOT RUN` | 超出授权或刻意不执行 | 无（必须写明为何不执行） |

附加约定：

- `PASS` 不得用于「未发现反例」；那是 `UNVERIFIED`。
- 「没找到测试」是 `UNVERIFIED`（缺什么证据：该行为的测试证据；最小补证：检索该行为的测试文件），不是 `PASS`。
- 一个单元可同时有多个维度的判定词，不要压成一句。
- 争议复核类任务：维持上一份报告的结论记为 `CONFIRMED`；推翻记为 `REVERSED`；既不能证实也不能证伪记 `UNVERIFIED`。这三个词只用于复核任务。

- **索引新建是写操作**（会改 AGENTS.md/CLAUDE.md），本次**不执行**。若某成员确需刷新，只能用 `gitnexus analyze --index-only`（完全不做文件注入）或 `--skip-agents-md`，并先向 captain 报备。

### 图谱已覆盖 vs 未覆盖

| 覆盖（可作为拓扑证据） | 未覆盖（必须用 E1/E4 补证，且不得声称「图谱确认」） |
|---|---|
| TS/TSX 符号定义与静态 import/call 边 | **Rust**（`src-tauri`，图谱未索引） |
| 跨 workspace package 的依赖边 | **动态加载**：字符串拼路径 `import()`、DI 容器、插件注册 |
| 同进程函数调用链与执行流 | **文件约定/配置驱动**：JSON/YAML/TOML 决定的装配（`tauri.conf.json`、路由表、合同表） |
| — | **HTTP 边界**：路由 → handler 的运行时连线、请求/响应契约 |
| — | **IPC 边界**：Tauri command、stdio 协议、launcher ↔ server |
| — | **事件协议**：CORS/事件总线/订阅语义 |
| — | **外部副作用**：真实模型调用、支付、文件系统落盘 |
| — | **构建产物一致性**：`dist/`、`dist-server/` 与源码的实际对应关系 |

**跨越未覆盖边界的结论，一律标注「图谱未覆盖」并降级到 E1/E4。**
