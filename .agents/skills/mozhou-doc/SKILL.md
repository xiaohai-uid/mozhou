# mozhou-doc

墨舟文档放置标准：**一个事实只有一个家**。写文档前先查表，写完问自己"这事别处记过吗"。

## 文档分工

| 内容 | 放在哪 | 说明 |
|---|---|---|
| 项目一句话 + 全局约定 | `CONTEXT.md`（根目录唯一） | 单上下文，不拆多份 |
| 架构地图 | `docs/` 下对应主题 | 只画地图，不展开细节 |
| 操作指南（怎么做） | `docs/` 下对应主题 | 步骤式，面向人 |
| spec-kit 产出 | `specs/` | spec / plan / tasks，按 spec-kit 规范 |
| 工单记录 | `.scratch/<project>/issues/NN-*.md` | 实现细节、试错过程 |
| AI 会话决策 | `.agents/notes/` | 轻量决策记录，见其 README |
| 正式架构决策 | `docs/adr/` | 按需懒创建，不提前写 |
| 技术预研结论 | `docs/spikes/` | spike 结论 |
| 包 / 应用的对外契约 | 各 package / app 的 README | 配置、限制、扩展点 |

## 写作规则

- 写**当前状态**，不写历史（"2026-08 曾经…"这种话不许出现在正文）
- 不写会腐烂的状态断言（"已实现！""即将支持"）；状态只活在工单和 CI 里
- 代码示例必须和源码一致；API 变了示例同步变，不许"示例仅供参考"
- 中文为主，代码标识符用英文原文，不翻译
- 单篇超过约 1500 字就拆分
- 不手写机器可生成的目录 / 表格（能生成的就生成，不维护第二份）
